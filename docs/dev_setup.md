# Developer Setup Guide

## Prerequisites

| Tool | Purpose | Install |
|------|---------|---------|
| Python 3.10+ | Engine + server | `brew install python` or [pyenv](https://github.com/pyenv/pyenv) |
| Node.js 20 LTS | Frontend build | `brew install node` or [Volta](https://volta.sh) |

No Rust. No Xcode.

---

## First-Time Setup

### 1. Clone the repo

```bash
git clone <repo-url>
cd Knowler
```

### 2. Python engine

```bash
cd engine
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

### 3. Frontend

```bash
cd app
npm install
```

---

## Running in Development

Run these two in separate terminals:

**Terminal 1 — Engine server**
```bash
cd engine
source .venv/bin/activate
python -m knowler_engine serve --dev --no-browser
# Starts FastAPI server at http://localhost:7842
# --dev enables verbose logging and debug mode
```

**Terminal 2 — Frontend with hot reload**
```bash
cd app
npm run dev
# Opens http://localhost:5173
# Vite proxies /api/* and /ws to the engine on port 7842
```

Open `http://localhost:5173` in your browser. Changes to React files reload instantly; changes to Python files require restarting the engine.

## Building for Production

The production build bundles the React frontend into the Python package so a single `pip install` is all users need.

```bash
# Full build: compile React and copy into engine package
make build

# Install locally
make install
knowler   # starts at http://localhost:7842
```

Or step by step:
```bash
# 1. Build React
cd app && npm run build

# 2. Copy into Python package
rm -rf engine/knowler_engine/static
cp -r app/dist engine/knowler_engine/static

# 3. Install
cd engine && pip install -e .
knowler
```

## Common Tasks

### Add a new IPC method

1. Add the handler in `engine/knowler_engine/__main__.py` inside `_register_handlers()`:
   ```python
   @router.method("myfeature.doThing")
   async def do_thing(params: dict, ctx: AppContext) -> dict:
       return {"result": "..."}
   ```
2. Call it from the frontend:
   ```ts
   const result = await engineCall("myfeature.doThing", { param: "value" });
   ```

### Add a new job type

1. Write a handler function in the relevant pipeline module:
   ```python
   async def handle_my_job(job_ctx: JobContext) -> None:
       ...
   ```
2. Register it in `_register_job_handlers()` in `__main__.py`:
   ```python
   job_runner.register("my_job_type", handle_my_job)
   ```
3. Enqueue it via any IPC handler:
   ```python
   job_id = await ctx.job_runner.enqueue(project_id, "my_job_type", {"key": "val"})
   ```

### Add a SQL migration

Create `engine/migrations/sqlite/000N_description.sql`. It will be applied automatically on next startup. Migrations are tracked in the `schema_migrations` table and are never re-applied.
